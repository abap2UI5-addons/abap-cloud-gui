# Contributing

Write abap2UI5 apps like classic ABAP reports - selection screens, WRITE lists,
ALV grids and report events, on ABAP Cloud and NW 7.02.

## Before you open a pull request

Read [AGENTS.md](AGENTS.md) first - it holds the layout, the release targets
and the rules of this repository. Then run what CI runs:

```sh
npm ci
npm run check
```

`npm test` is an alias for `npm run check`. The ABAP Unit tests
(`npm run unit`) and the tests of the report converter
(`npm run test:report2ui5`) run separately; CI runs them too.

## What the gates are

| Gate | What it proves |
| --- | --- |
| `npm run lint` | abaplint: syntax and style, resolved against the abap2UI5 core |
| `npm run check:regex` | no regular expressions in `src/` |
| `npm run check:cloud` | the same source compiles under ABAP Cloud restrictions |
| `npm run check:702` | a scratch copy downports to 7.02 and passes abaplint there |
| `npm run check:abap2ui5` | [abap2UI5-linter](https://github.com/abap2UI5/linter): the app classes and the views they build |
| `npm run rename` | the namespace rename still applies cleanly |
| `npm run unit` | the ABAP Unit tests pass in the transpiled abap2UI5 backend (not part of `npm run check`) |
| `npm run test:report2ui5` | the report converter: its snapshots, and abaplint over what it writes (not part of `npm run check`) |

`src/03` is generated by the converter - never edit it by hand
(`UPDATE_SNAPSHOTS=1 npm run test:report2ui5` writes it).

## Conventions

English for code, comments, commit messages and pull requests. Commit subjects
are written in the imperative and describe the outcome, not the mechanics. One
topic per pull request. The wider rules the whole ecosystem follows live in
[abap2UI5's CONVENTIONS.md](https://github.com/abap2UI5/abap2UI5/blob/main/.github/shared/CONVENTIONS.md).
