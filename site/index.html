No SAP GUI on ABAP Cloud

No selection screens, no lists, no CL_SALV_TABLE. A report of ten minutes on premise turns into RAP, CDS and a Fiori app. abap-cloud-gui keeps the report model and renders it with abap2UI5.

The concepts you know

Event blocks are methods of the same name, PARAMETERS and SELECT-OPTIONS are attributes, write( ) writes the list, alv( ) shows a grid - with drilldown, value helps, variants and messages. No UI5 knowledge needed.

Converted, not rewritten

report2cloud turns a .prog.abap into a report class: FORMs into methods, the list and the ALV into their counterparts, dynpros and SAP GUI controls into stand-ins. What it cannot convert it refuses with the line - it never guesses.

A report as a class

CLASS zcl_hello DEFINITION PUBLIC INHERITING FROM z2ui5_cl_cgui_report FINAL CREATE PUBLIC.
  PUBLIC SECTION.
    DATA p_name  TYPE string.
    DATA p_times TYPE i.
  PROTECTED SECTION.
    METHODS selection_screen REDEFINITION.
    METHODS start_of_selection REDEFINITION.
ENDCLASS.

CLASS zcl_hello IMPLEMENTATION.
  METHOD selection_screen.
    screen->parameter( val = p_name text = `Your name` obligatory = abap_true
        )->parameter( val = p_times text = `Lines` ).
  ENDMETHOD.

  METHOD start_of_selection.
    write( |Hello { p_name }!| )->uline( ).
    DO p_times TIMES.
      write( |Line { sy-index }| )->new_line( ).
    ENDDO.
  ENDMETHOD.
ENDCLASS.

Start it like any abap2UI5 app (?app_start=zcl_hello): the selection screen comes up, Execute runs the report and shows the list, Back returns.

report2cloud playground

Paste a classic report of your own, or pick an example, and it is converted as you type. The converter runs in this page - the same code as npm run report2cloud; nothing is sent anywhere. Includes and the repository's DDIC are not there, so a report that needs them converts with TODOs.
